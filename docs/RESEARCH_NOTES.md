# Implementation research and source decisions

The supplied implementation plan is the design and scope authority. Local checkpoint configuration and installed library source were checked before introducing compatibility changes. Only official project/library documentation and NASA/NIST records were used for technical and scientific implementation decisions.

- [Transformers EmbeddingGemma 2 documentation](https://huggingface.co/docs/transformers/en/model_doc/embedding_gemma2) documents passing `vision_config=None` and `audio_config=None` through SentenceTransformers `config_kwargs`. The actual uploaded model records Transformers 5.22.1, SentenceTransformers 6.2.0 and Torch 2.11.0; the tested CPU environment preserves those versions. Local 6.2.0 source showed that the original multimodal `AutoProcessor` still needs CPU Torchvision during export. The serving export keeps the same tokenizer and verifies identical text input IDs/masks and embeddings after reload.
- The supplied model card identifies the original base revision `f9972ac22e696a105c482202646979e33e4b5a1e`. The [official Google model repository](https://huggingface.co/google/embeddinggemma-2/tree/f9972ac22e696a105c482202646979e33e4b5a1e) was checked at that immutable revision, downloaded anonymously under its Apache-2.0 metadata, and verified against upstream LFS weight hashes. Its separate CPU text export/index supports the offline comparison; it is never a production fallback or replacement for the supplied fine-tuned checkpoint.
- [Gemini structured-output documentation](https://ai.google.dev/gemini-api/docs/structured-output) supports schema-constrained output. The adapter uses a bounded REST call, then separately validates allowlisted evidence IDs, lane associations and prohibited claims. The model ID must be available to the user's key; no availability or live latency is claimed before the key is supplied. Schema compliance cannot establish factual entailment.
- NASA source choices, file hashes, native units and PDF page locators are documented in [the source review handoff](SOURCE_REVIEW.md) and [the source manifest](../data/manifests/sources.json). The October 28 package was absent. PSI catalog pointers and linked report evidence are distinguished from raw PSI data imports. Challenge-resource flags follow the supplied plan and associated catalog records; the exact current challenge resource list still needs confirmation against the event page/package.
- [MDN's pixel-art guidance](https://developer.mozilla.org/en-US/docs/Games/Techniques/Crisp_pixel_art_look) informs nearest-neighbor artwork display. Five short CSS sprite steps at about seven frames per second provide one bounded decorative effect. All text, data and labels remain HTML. Lossless WebP encoding reduced the original 256×144 PNG from 53,596 to 31,904 bytes.
- [Animation performance guidance](https://web.dev/articles/animations-guide) and [Core Web Vitals definitions](https://web.dev/articles/vitals) informed transform/opacity motion, stable data labels and separate lab reporting. Browser timing, frontend transfer estimates, CPU encoding time and field INP are not interchangeable. No field INP or VPS result is invented.
